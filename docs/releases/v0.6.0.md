# CRDD IR v0.6.0

v0.6.0 extends portable structured-data generation for object collections in
Unreal C++ and Unity C#.

## Added

- `IR-STRUCTURAL-TYPE-001`: deterministic reuse of one generated element type
  for top-level object collections with the same generated shape
- `IR-NESTED-COLLECTION-001`: primitive arrays inside object collection
  elements, including empty arrays and order preservation
- deterministic collision handling when different shapes prefer the same
  target type name
- Target Parity Evidence attribution for both v0.6.0 requirements
- cross-target fixtures covering Input, State, whole-collection effects,
  canonical Evidence, uniqueness, rollback, and deterministic regeneration

## Target mapping

- Unreal: object elements become one reusable struct and nested primitive
  arrays become `TArray<T>` members
- Unity: object elements become one reusable class and nested primitive arrays
  become `List<T>` members

The generated Input and State collection fields reference the same target type
when their element shapes match, including when the Source Contract field names
differ.

## Compatibility

The Source Contract and Core IR schemas already represented nested arrays, so
no Source Contract migration is required. Existing v0.5.0 contracts retain
their operation semantics. Generated files and manifests must be regenerated
because type declaration ownership and Generator identity change in v0.6.0.

The v0.6.0 target surface supports primitive arrays nested in object collection
elements. Nested object collections, nested maps, and nested unions remain
outside this release's generated target surface.
