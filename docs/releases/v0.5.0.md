# CRDD IR v0.5.0

v0.5.0 adds portable compound values and reversible Evidence projection to
the Unreal C++ and Unity C# targets.

## Added

- `IR-UNION-001`: discriminated unions with generated variant enums, typed
  payloads, explicit `Unknown` state, schema validation, and deterministic
  fixtures for every declared variant
- `IR-PRIMITIVE-COLLECTION-001`: ordered primitive arrays, including empty
  arrays, bounds, and keyless `collection.unique`
- `IR-EVIDENCE-ROUNDTRIP-001`: canonical UTF-8 JSON and SHA-256 validation for
  compound Evidence
- generated canonical serializers for Unreal and Unity using Source Contract
  field names, sorted object keys, and source-order arrays
- byte-identical JSON escaping for controls, Unicode scalar values, and
  unpaired UTF-16 surrogates
- compile-time rejection of binary floating-point fields in canonical Evidence;
  exact Evidence numbers use canonical decimal strings
- cross-scope input-to-state projection for object and union values without
  flattening
- isolated conformance cases for hash modification, primitive duplicates,
  rollback, and every union variant
- Target Parity attribution for all three v0.5.0 requirements

## Evidence semantics

`evidence.canonical-hash` hashes the selected top-level `input` or `state`
record after removing its configured hash field. Object keys are sorted;
array order is significant. Missing or modified Evidence is rejected before
effects run, preserving the original state.

Unknown union variants are represented explicitly and are never converted to
a declared default variant. The Source validator and simulator fail closed on
an undeclared discriminator.

## Compatibility

The changes are additive. Existing v0.4.0 Source Contracts remain valid and
generate the same operation semantics. Generated files and batch manifests
must be regenerated after upgrading because the generator identity changes to
`0.5.0`.

The new compound-value target support is currently scoped to top-level
input/state fields. Union variants contain object payloads. Primitive
collections support scalar array elements; nested collection and nested union
declarations remain outside the supported target-generation surface.
Binary floating-point fields cannot participate in `evidence.canonical-hash`.
This prevents runtime-specific spellings of `-0`, exponent boundaries,
subnormals, and maximum finite values from changing the digest.
