# CRDD IR v0.3.0

v0.3.0 establishes CRDD IR as a general application-contract compiler while
keeping Unreal Engine and Unity as independent Target Adapters.

## Highlights

- Commands, read-only queries, synchronous and asynchronous execution
- Recursive objects, typed arrays and maps, nullable and optional fields, and
  discriminated unions
- Output contracts, cancellation, timeout, idempotency, and emitted events
- Target-neutral TypeScript DTO, validator, and handler-boundary generation
- External Target Adapter modules loaded through `--target-module` or project
  configuration without modifying Core or CLI dispatch
- Versioned Extension envelopes with owner-defined payload validation
- Target-neutral 3D Asset vocabulary translated at the Unreal boundary
- One generic project configuration and batch-generation path for all targets
- Deterministic generation ownership, CRLF-safe hashes, process locking,
  conformance bundles, regression manifests, and traceability evidence

## Core boundary

Core owns operation identity, typed input/state/output, requirements, errors,
effects, transactions, execution semantics, and emitted-event contracts. It
does not own a game, engine, UI, transport, database, or deployment model.

Target- or domain-specific information belongs in a versioned Extension.
Adapters declare the Extension protocols they consume and must fail closed when
portable Core semantics cannot be represented.

## Target adapters

Built-in adapters cover canonical IR, conformance/evidence, 3D source assets,
TypeScript, Unreal C++, and Unity C#. Additional adapters can self-register:

```powershell
node .\tools\CRDD-IR\src\cli.ts generate custom-target `
  .\contracts\operation.md `
  --target-module .\tools\custom-target.mjs `
  --out-dir .\generated\custom
```

A project target may alternatively declare a project-relative `module` in
`crdd-ir.config.json`.

## Compatibility

- Product and generated-code version: `0.3.0`
- Node.js: `22.18.0` or later
- Unreal verification baseline: Unreal Engine 5.8, Win64
- Unity verification baseline: Unity 6, Windows x64, IL2CPP
- Source Contract protocol: `crdd-source-contract/v0.1`
- Internal IR version: `0.1`
- v0.3.0 intentionally removes pre-release repository-layout assumptions
- Core protocol identifiers remain stable; new application semantics are
  additive and unsupported adapters fail closed

## Upgrade from v0.2.1

```powershell
git -C tools/CRDD-IR fetch origin --tags
git -C tools/CRDD-IR checkout v0.3.0
npm.cmd ci --prefix tools/CRDD-IR

.\tools\crdd-ir.ps1 doctor
.\tools\crdd-ir.ps1 generate
.\tools\crdd-ir.ps1 verify
```

Regenerate owned outputs after upgrading. If a project previously depended on
repository-specific source or evidence directory names, update
`crdd-ir.config.json` to declare those paths explicitly.

## Known boundaries

- Installer scaffolding remains Unreal-oriented; Unity project assembly
  placement remains product-owned
- Python, web API, database, and Electron/React adapters are extension points,
  not bundled generators
- Engine runtime projection and domain implementation remain product-owned
- Third-party Target Adapter modules execute with the privileges of the CLI and
  must be pinned and reviewed like any build dependency
