# CRDD IR v0.2.1

v0.2.1 generalizes CRDD IR Core beyond game development while preserving the
Unreal Engine and Unity target workflows introduced in v0.2.0.

## Highlights

- Domain- and target-neutral Core IR boundary
- Versioned `operation.extensions` envelope
- 3D Asset semantics moved to the `crdd.3d-assets` Extension
- Asset-specific validation owned by the `assets` target
- Arbitrary matching units such as `USD`
- Non-game `AuthorizeInvoice` reference fixture
- Order-independent adapter result comparison
- Machine-readable Target Registry Extension ownership

## Core and Extension boundary

Core IR owns:

- operation identity and CRDD traceability
- typed input and state
- requirements and error contracts
- state effects
- transaction and rollback semantics

Domain- or target-specific data is represented as:

```yaml
extensions:
  com.example.audit:
    protocol: example/audit-v1
    data:
      category: billing
```

Core validates the Extension envelope. The consuming Target Adapter validates
the payload.

CRDD Markdown `assets:` remains accepted as frontend shorthand and is normalized
to:

```yaml
extensions:
  crdd.3d-assets:
    protocol: crdd-ir/3d-assets-v0.1
    data:
      assets: []
```

## Compatibility

- Product and generated-code version: `0.2.1`
- Node.js: `22.18.0` or later
- Unreal verification: Unreal Engine 5.8, Win64
- Unity verification: Unity 6, Windows x64, IL2CPP
- Source Contract protocol: `crdd-source-contract/v0.1`
- Internal IR version: `0.1`
- Existing v0.1 IR containing `operation.assets` remains readable
- New compilation emits 3D data through `operation.extensions`
- Unreal and Unity command aliases remain available

The IR digest changes for contracts containing `assets:` because the canonical
IR now stores those assets in the versioned Extension. Generated implementation
semantics and 3D source assets remain unchanged.

## Upgrade from v0.2.0

```powershell
git -C tools/CRDD-IR fetch origin --tags
git -C tools/CRDD-IR checkout v0.2.1
npm.cmd ci --prefix tools/CRDD-IR

.\tools\CRDD-IR\scripts\repair-project.ps1 -ProjectRoot .
.\tools\crdd-ir.ps1 doctor
.\tools\crdd-ir.ps1 verify
```

Regenerate owned outputs after upgrading. The ownership manifest will update
the IR digest and generated-code version. Do not manually copy the temporary
Internal IR into the adopting repository as a second source of truth.

## Known boundaries

- Installer and repair scaffolding remain Unreal-oriented
- Unity asmdef placement remains owned by the adopting Unity project
- Built-in automatic unit conversion is currently provided for `m`, `cm`, and
  `mm`; arbitrary units are accepted when both sides use the same unit
- Extension payload schemas and validators are supplied by their owner rather
  than dynamically discovered from third-party packages
- Web, server, database, and API code-generation targets are not bundled yet
- Engine runtime projection remains product-owned
