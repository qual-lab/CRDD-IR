# CRDD IR v0.10.0

v0.10.0 adds deterministic collection evaluation for policy-driven operations
without moving join, scoring, or authoritative-data decisions into product
adapters.

## Added

- typed `count` and `sum` expressions with explicit item aliases and filters
- typed `join_count` and `join_sum` expressions over two arrays or maps
- role/group aggregation through typed predicates
- deterministic collection counterexample generation for Conformance bundles
- `visibility: private` input metadata and direct output/event projection guards
- compile-time aggregate overflow proofs from collection and numeric bounds
- parity attribution for collection aggregation and private-output boundaries
- cross-runtime coverage for empty selection, duplicates, unknown IDs, invalid
  records, revision conflict, atomic reward rollback, output, and events

## Changed

- multiplication and division are part of the numeric expression grammar
- Conformance mutation can now shrink, duplicate, and modify collection values
  while preserving Source Contract validation
- version metadata is `0.10.0`

## Compatibility and cleanup

This release does not provide a compatibility adapter for any former
product-specific evaluation operation. Consumers should define a new operation
using the generic collection expressions and keep product policy values in
their Source Contract input/policy schema.

No product-specific evaluator or legacy-operation shim is retained in Core IR.
Stable CRDD Source Contract and target protocols remain supported because they
are active toolchain contracts, not product compatibility code.
