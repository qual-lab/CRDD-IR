# CRDD IR v0.3.1

v0.3.1 fixes composite arithmetic boundary generation so strict/inclusive
comparison mutations cannot survive without an explicit diagnostic.

## IR-TEST-003

For affine comparisons containing addition or subtraction, the conformance
generator now deterministically emits:

- an exact equality case
- a failing case one representable unit outside the boundary
- a successful case one representable unit inside the boundary

Supported comparison operators are `<=`, `<`, `>=`, and `>`. Changing an
inclusive operator to its strict equivalent, or vice versa, changes the
equality-case outcome and kills the mutation.

## Safety

Generated cases:

- preserve all non-target Requires
- satisfy field type, `minimum`, and `maximum`
- preserve source units
- use the built-in one-millimetre-equivalent quantum for length units
- use one unit for integer and project-defined unit fields
- reject non-finite and unsafe arithmetic
- remain byte-deterministic for the same IR

`project doctor` reports `CRDD_BOUNDARY_CASE_UNSATISFIABLE` or
`CRDD_BOUNDARY_CASE_UNSUPPORTED` with the Requires ID, expression, reason, and
conflicting Schema/Requires details when a valid isolated case cannot be
generated.

## Upgrade from v0.3.0

```powershell
git -C tools/CRDD-IR fetch origin --tags
git -C tools/CRDD-IR checkout v0.3.1
npm.cmd ci --prefix tools/CRDD-IR

.\tools\crdd-ir.ps1 doctor
.\tools\crdd-ir.ps1 generate
.\tools\crdd-ir.ps1 verify
```

Regenerate owned conformance outputs after upgrading. Existing Source Contract
and Internal IR protocol versions remain unchanged.
